# VE table calibration from engine sensor logs

https://github.com/Lotopot21/MMA3001-ve-calibration/

An offline tool that corrects an engine's volumetric efficiency (VE) table from
logged air/fuel ratio data, and computes the resulting injector pulse widths.
This is the core step in calibrating a fuel injected car or motorcycle ECU.

The package also contains a forward engine model that generates synthetic logs
from a known ground truth VE surface, so the calibration can be validated
against an answer the pipeline never sees.

MMA3001 Numerical Methods and Machine Learning — individual project.

## The problem

An ECU meters fuel by estimating how much air entered the cylinder. It does
this with the speed/density relation: cylinder volume times air density times a
volumetric efficiency read from a lookup table. If that table is wrong, the
fuel is wrong, and the engine runs lean or rich.

The measured air/fuel ratio reveals the error directly:

```
AFR_measured / AFR_target = VE_true / VE_table
```

so the ratio of measured to target mixture is exactly the factor by which the
table underreads. The difficulty is not the arithmetic, it is that a log
samples the operating range unevenly, contains conditions where the reading
means nothing, and covers only part of the table.

## Usage

Calibrate a table from a synthetic log:

```python
from vetuner.drive_cycle import generate_drive_cycle
from vetuner.engine_model import simulate_engine
from vetuner.iteration import iterate_calibration
from vetuner.sensors import apply_sensor_model
from vetuner.ve_surface import BASE_MAP_SURFACE, ve_table

cycle = generate_drive_cycle()
starting_table = ve_table(params=BASE_MAP_SURFACE)

history = iterate_calibration(
    cycle, starting_table, gain=0.6, max_passes=5, method="gaussian_process"
)
calibrated = history.final_table
```

Produce the injector output and export it:

```python
from vetuner.pulse_width import export_table_csv, pulse_width_map

result = pulse_width_map(calibrated)
print(f"peak injector duty: {result.max_duty:.0%}")

export_table_csv("outputs/ve_table.csv", calibrated)
```

The notebooks in `notebooks/` reproduce every figure and result quoted below,
one per project phase.

## Inputs and outputs

### Inputs

The pipeline consumes a time series of measured channels, sampled uniformly.

| Channel | Units | Domain | Meaning |
|---|---|---|---|
| `time_s` | s | increasing | Sample time |
| `rpm` | rpm | 0–7000 | Engine speed |
| `map_kpa` | kPa absolute | 8–101 | Manifold pressure |
| `iat_c` | °C | −40 to 120 | Intake air temperature |
| `tps` | fraction | 0–1 | Throttle position |
| `afr` | mass ratio | 8–22 | Measured air-fuel ratio |
| `batt_v` | V | 10–15 | Supply voltage |

All quantities are SI internally; conversion happens only at the boundary.

Samples outside the table axes, during overrun fuel cut, during the sensor's
recovery from overrun, during transients, or carrying implausible readings are
detected and discarded rather than used. See **Validation** for why each
matters.

### Outputs

| Output | Units | Meaning |
|---|---|---|
| Corrected VE table | fraction | Volumetric efficiency at each grid node |
| Per cell sample counts | — | How much data supports each cell |
| GP uncertainty | fraction | Where the estimate is unsupported |
| Injector pulse width map | ms | Commanded pulse at reference conditions |
| Injector duty map | fraction | Fraction of cycle time used |

The default table is 16 speed breakpoints by 12 load breakpoints.

A pulse width map applies only at the stated intake temperature and supply
voltage, because pulse width depends on both. An ECU stores the VE table and
computes pulse width at run time; the pulse width map is a verification and
sizing artefact.

**Intended use.** This is an offline analysis tool producing a suggestion for a
human tuner to review. It is not a closed loop controller, and its output
should not be flashed to an engine without inspection. A VE table that is wrong
in the lean direction under load will damage an engine.

## Approach

1. **Forward model** — a known VE surface drives a speed density engine model.
   A deliberately miscalibrated table drives the simulated ECU, so the
   resulting AFR error is proportional to the table error.
2. **Sensor model** — lag, noise, quantisation and optionally exhaust
   transport delay are applied to the measurements only.
3. **Gating** — samples whose AFR cannot be attributed to a known operating
   point are rejected.
4. **Surface fitting** — the scattered correction factors are fitted onto the
   table grid.
5. **Iteration** — the correction is applied as a damped fixed point update
   and repeated.
6. **Pulse width** — the calibrated table is converted to injector commands
   and checked against duty limits.

## Validation

Validation uses a **manufactured solution**: a known true VE surface generates
the data, and the pipeline is scored on how closely it recovers that surface.
The truth is never exposed to the calibration path, which is enforced
structurally — the log object contains no reference to it, and a test asserts
this.

Two independent metrics are reported. Table RMSE compares against the known
truth, which is only possible with synthetic data. Held out AFR error scores
the calibrated table on a second drive cycle never used to fit it, which is
measurable on a real engine and so transfers to real logs.

Verification is separate from validation. The forward model is verified by
confirming that a correct table produces target mixture to machine precision at
table nodes; the iteration is verified against the analytic convergence rate of
a damped fixed point scheme; the filters are verified against closed form
results (a polynomial passes a Savitzky Golay filter unchanged; the Kalman gain
matches the steady state solution of the Riccati equation).

342 tests run under pytest and in CI on every push.

|---|---|---|
| Starting map | 7.18 | 10.26% |
| Naive correction, no gating | 10.41 | 3.89% |
| Gated, per-cell averaging | 6.37 | 3.83% |
| Gated, Gaussian process | 1.45 | 1.02% |
| Iterated bilinear, gain 0.6 | 5.60 | 0.68% |
| Iterated Gaussian process, gain 0.6 | 1.20 | 0.45% |

| Method | RMSE | Visited | Unvisited | Time |
|---|---|---|---|---|
| Per-cell averaging | 6.37 | 0.70 | 6.99 | 1.5 ms |
| Bilinear scatter | 5.60 | 0.55 | 6.15 | 1.3 ms |
| Global polynomial | 18.67 | 1.76 | 20.50 | 40.0 ms |
| Thin plate spline | 2.64 | 0.62 | 2.89 | 1.9 ms |
| Gaussian process | 1.50 | 0.56 | 1.63 | 59.0 ms |

## Limitations

- **Coverage is the binding constraint.** The default drive cycle reaches only
  35% of table cells. No fitting method can correct a cell the engine never
  visited; the Gaussian process is used because its variance identifies those
  cells rather than silently extrapolating into them.
- **The iteration converges to the wrong fixed point.** Because the ECU reads
  the table by interpolation, the scheme converges to whichever table makes the
  *interpolated* read produce target mixture, which differs from the truth by
  the interpolation error. Accuracy therefore reaches a minimum after a few
  passes and degrades slowly thereafter, so the stopping criterion is based on
  held out error rather than on the size of the table update.
- **Manifold pressure bias is the dominant error source.** A systematic 5
  kPa offset costs 1.15 percentage points of AFR accuracy, far more than
  any random noise, and is absorbed silently into the table.
- **Filtering was implemented and found unnecessary.** Noise is not a limiting
  factor here, because per cell averaging already reduces it by √n and gating
  removes the samples where a noisy reading would be misattributed.
- **Validation is against a model, not an engine.** The synthetic data
  establishes that the estimator recovers a VE surface from data produced by
  this engine model. It does not establish that the model resembles a real
  engine. Real logs would be needed for that.
- Fuel film dynamics (wall wetting) are not modelled; the affected samples are
  gated out instead.

## Project structure

```
src/vetuner/
├── ve_surface.py     Ground truth VE surface and miscalibrated base map
├── drive_cycle.py    Operating point trajectory and throttle model
├── engine_model.py   Speed density, ECU fuelling, resulting AFR
├── sensors.py        Lag, noise, quantisation
├── sensor_health.py  Instrument fault screening before calibration
├── faults.py         Deliberate sensor faults, for testing the screening
├── gating.py         Sample acceptance criteria
├── surface_fit.py    Six scattered data fitting methods
├── correction.py     Correction factors and table update
├── iteration.py      Damped fixed point iteration
├── metrics.py        Table and fuelling accuracy
├── pulse_width.py    Injector output and CSV export
├── transport.py      Exhaust transport delay
├── filtering.py      Moving average, Savitzky Golay, Kalman
├── performance.py    Timing, FLOP estimates, profiling support
└── units.py          Unit conversions

tests/                pytest suite, one file per module
notebooks/            One notebook per project phase
scripts/              Figure generation for the report
docs/                 Generated API documentation
```
